# 파이프라인 테스트 EC2 관리 판단

## 목적

남아 있는 테스트 EC2를 Terraform 관리 대상으로 편입할지 결정하기 위해 현재 상태, 프로젝트 사용 근거, 종속 자원의 소유 범위를 확인.

Terraform 편입은 기존 자원을 계속 운영하고 변경 이력을 관리하겠다는 결정에 가까움. 사용 목적이 끝난 임시 서버까지 편입하면 불필요한 코드와 state가 남으므로 장기 관리 가치 확인을 먼저 수행.

## 확인 결과

- 이름과 기존 인벤토리에서 테스트 용도로 분류
- 장기간 중지 상태이며 프로젝트 문서와 코드에서 해당 서버를 직접 참조하는 근거 없음
- 전용 IAM 연결과 시작 자동화 설정 없음
- 연결 보안 그룹은 여러 프로젝트 EC2가 공유하므로 이 서버와 함께 편입할 수 없음
- 루트 볼륨 외 별도 데이터 볼륨 없음

중지 상태와 참조 부재만으로 불필요한 자원이라고 단정할 수는 없음. 서버 내부에 문서화되지 않은 테스트 결과나 설정이 남아 있을 수 있으므로 담당자 확인 전에는 편입·시작·삭제하지 않음.

## 판단

현재 결론은 **Terraform 편입 보류**.

장기 운영 대상이라는 근거가 확인되면 EC2 속성을 다시 조회하고 변경 없는 import 계획을 작성. 실험이 끝난 임시 자원으로 확인되면 Terraform 관리 대상으로 만들지 않고, 데이터 보존 필요성을 검토한 뒤 별도 정리 절차 진행.

## 팀 확인 항목

- 앞으로 다시 사용할 계획이 있는지
- 서버 내부에 보존해야 할 코드·설정·데이터가 있는지
- 현재 Airflow 기반 파이프라인으로 역할이 대체됐는지
- 자원 유지 책임자와 종료 판단 시점이 누구인지

## 결과별 후속 작업

| 확인 결과 | 후속 작업 |
|---|---|
| 계속 사용 | 전용 자원 경계 재확인 후 EC2 변경 없는 import 준비 |
| 사용 종료, 데이터 보존 필요 | 볼륨 백업과 복원 확인 후 정리 계획 작성 |
| 사용 종료, 보존 불필요 | 승인된 별도 작업에서 자원 정리 |
| 판단 보류 | 소유자·용도·재검토일 태그 개선안을 별도 작성 |

## 한계

- 읽기 전용 AWS 조회와 저장소 검색만 수행했으며 서버 내부 파일은 확인하지 않음
- 최근 감사 이벤트 조회 범위 밖의 과거 사용 이력은 확인할 수 없음
- 이번 판단 과정에서 AWS 자원을 생성·수정·시작·삭제하지 않음
