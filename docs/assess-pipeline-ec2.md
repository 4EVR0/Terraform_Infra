# 논문 크롤링 EC2 관리 판단

## 목적

장시간 실행되는 화장품 성분 논문 크롤링을 로컬 컴퓨터 대신 수행하기 위해 만든 EC2를 Terraform 관리 대상으로 편입할지 판단.

Terraform 편입은 기존 자원을 계속 운영하고 변경 이력을 관리하겠다는 결정에 가까움. 사용 목적이 끝난 임시 서버까지 편입하면 불필요한 코드와 state가 남으므로 장기 관리 가치 확인을 먼저 수행.

## 확인 결과

- 논문 크롤링처럼 로컬 컴퓨터를 계속 켜두기 어려운 장시간 작업의 실행 환경으로 생성
- 크롤링 작업 이후 장기간 중지 상태이며 향후 재사용 여부는 아직 확정되지 않음
- 프로젝트 문서와 코드에는 해당 EC2의 생성·배포·복구 방법이 남아 있지 않음
- 전용 IAM 연결과 시작 자동화 설정 없음
- 연결 보안 그룹은 여러 프로젝트 EC2가 공유하므로 이 서버와 함께 편입할 수 없음
- 루트 볼륨 외 별도 데이터 볼륨 없음

현재 서버는 상시 운영 서비스보다 필요할 때 실행하는 배치 작업 환경에 가까움. 서버 내부에 크롤링 코드·결과·체크포인트가 남아 있을 수 있으므로 보존 대상을 확인하기 전에는 삭제하지 않음.

## 판단과 실행 결과

최종 결론은 **기존 EC2를 Terraform에 편입하지 않고 복구용 AMI 생성 후 폐기**.

다시 논문 크롤링을 실행할 가능성이 생기면 현재 EC2를 그대로 보존하는 방식보다 동일한 실행 환경을 필요할 때 재생성할 수 있도록 구성하는 방향을 우선 검토. Terraform은 EC2·전용 보안 그룹·최소 권한 IAM 등 인프라를 만들고, 크롤러는 컨테이너 또는 시작 스크립트로 배포하며, 결과와 체크포인트는 S3 같은 영구 저장소에 보관하는 구조를 권장.

Terraform import만으로 서버 내부 데이터가 백업되거나 복원되지는 않음. 실행 구성과 루트 디스크를 포함한 비공개 AMI를 만들고 AMI와 스냅샷 완료 상태를 확인한 뒤 EC2를 종료. 종료 시 삭제되도록 설정된 기존 루트 볼륨의 삭제도 확인.

파이프라인 종료 후 공용 SSH 보안 그룹의 마지막 사용처가 사라짐. 그룹과 규칙 세 개만 제거하는 Terraform 계획을 별도 검증하고 적용 대기.

## 재사용 시 확인 항목

- 앞으로 다시 사용할 계획이 있는지
- 서버 내부에 보존해야 할 코드·설정·데이터가 있는지
- 크롤링 결과와 체크포인트를 외부 저장소에 보관할 수 있는지
- 컨테이너 이미지 또는 시작 스크립트로 실행 환경을 재현할 수 있는지
- 자원 재검토 시점을 언제로 둘지

## 결과별 후속 작업

| 확인 결과 | 후속 작업 |
|---|---|
| 반복 사용 예정 | Terraform으로 필요할 때 생성 가능한 크롤링 실행 환경 설계 |
| 현재 서버를 그대로 재사용 | 내부 상태 확인 후 EC2 변경 없는 import 검토 |
| 사용 종료, 데이터 보존 필요 | 볼륨 백업과 복원 확인 후 정리 계획 작성 |
| 사용 종료, 보존 불필요 | 승인된 별도 작업에서 자원 정리 |
| 판단 보류 | 용도·소유자·재검토일 태그 개선안을 별도 작성 |

## 재사용 시 권장 구조

1. Terraform으로 크롤링 EC2와 전용 네트워크·최소 권한 IAM 생성
2. 버전이 고정된 컨테이너 이미지 또는 시작 스크립트로 크롤러 배포
3. 크롤링 결과와 재시작용 체크포인트를 영구 저장소에 기록
4. 작업 완료 후 인스턴스를 중지하거나 제거
5. 다음 실행 시 동일한 코드로 환경 재생성

이 구조는 현재 서버 한 대의 내부 상태에 의존하지 않고 작업 환경과 결과 데이터의 수명 주기를 분리. Terraform 도입의 효과도 기존 테스트 서버를 state에 등록하는 데서 끝나지 않고 반복 실행·복구 가능성으로 이어짐.

## 한계

- 읽기 전용 AWS 조회와 저장소 검색만 수행했으며 서버 내부 파일은 확인하지 않음
- 최근 감사 이벤트 조회 범위 밖의 과거 사용 이력은 확인할 수 없음
- 재사용 시 필요한 인스턴스 사양과 실행 시간은 실제 크롤링 측정 후 결정 필요
- AMI와 스냅샷의 완료 상태는 확인했지만 실제 복원 인스턴스 부팅은 시험하지 않음
- AMI 보존 기간과 최종 삭제 시점은 별도 결정 필요

세부 폐기 및 네트워크 정리 절차는 [논문 크롤링 EC2 안전 폐기](retire-pipeline-ec2.md) 참조.
