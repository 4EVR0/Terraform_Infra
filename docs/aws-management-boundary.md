# AWS 인벤토리 관리 경계

## 목적

- 프로젝트 관련 AWS 자원을 조사하고 이 저장소의 관리 범위 확정
- 모든 발견 자원을 무조건 import하지 않고 실제 변경 주체에 따라 소유권 분리
- Terraform과 애플리케이션·AWS 서비스의 이중 관리 방지

## 조사 근거

- 계정에서 활성화된 17개 리전의 지원 서비스 API를 읽기 전용으로 조회
- EC2·EBS·네트워크·S3·ECR·Glue·IAM·CI 연결 자원과 운영 서비스 확인
- 561건의 API 응답을 로컬 원본으로 보관하고 미해결 조회 오류가 없음을 확인
- 실제 식별자·정책 본문·접속 정보는 Git 제외 로컬 기록에만 보관
- 이 조사는 도구에 구현된 API 범위를 대상으로 하며 AWS의 모든 서비스와 하위 자원을 완전 탐색한다는 의미는 아님

## 최종 관리 경계

| 분류 | 대상 | 처리 기준 |
|---|---|---|
| Terraform 관리 | 공용 상태 저장소와 보호 설정 | bootstrap 상태에서 관리 |
| Terraform 관리 | 모니터링·Airflow·GraphDB EC2 | 기존 자원을 project 상태에 연결하고 주요 속성 관리 |
| Terraform 관리 | 세 서버의 전용 보안 그룹·규칙 | 서버별 통신 규칙 관리 |
| Terraform 관리 | 세 서버에 연결된 역할·인스턴스 프로파일·정책 연결 | 프로젝트가 소유한 연결 관계 관리 |
| Terraform 관리 | 모니터링 데이터 버킷의 기본 보호 설정 | 버킷 본체·암호화·공개 접근 차단·소유권 설정 관리 |
| Terraform 관리 | Terraform 운영 역할과 팀 공통 관리자 역할 | bootstrap 상태에서 접근 경로와 보호 정책 관리 |
| 조회만 수행 | 기본 VPC·서브넷·라우팅·인터넷 게이트웨이 | 계정 기본 네트워크를 재생성하지 않고 기존 ID 참조 |
| 조회만 수행 | AWS 관리형 IAM 정책 | 정책 자체는 AWS가 관리하며 필요한 연결 관계만 Terraform에서 관리 |
| 외부 관리 | Glue 데이터베이스·테이블과 Athena 기본 작업 그룹 | 데이터 파이프라인 또는 AWS 서비스가 생성·갱신하므로 Terraform 관리에서 제외 |
| 외부 관리 | ECR 저장소·GitHub OIDC·CI 역할 | 애플리케이션 빌드·배포 영역으로 분리하고 기존 워크플로의 책임 유지 |
| 외부 관리 | 홈서버 서비스 IAM 사용자와 정책 | 외부 실행 주체의 자격 증명 운영 범위로 분리 |
| 외부 관리 | 데이터 파이프라인 버킷 | 데이터 수명 주기와 파이프라인 변경 주체가 관리 |
| 외부 관리 | AMI·EBS 스냅샷 등 백업 산출물 | 운영자가 보존·삭제를 판단하는 복구 산출물로 분리 |
| 관리 제외 | AWS 서비스 연결 역할·기본 보안 그룹·AWS 관리형 KMS 별칭 | AWS 또는 계정 기본 자원으로 판단 |
| 관리 제외 | 프로젝트 소유 근거가 확인되지 않은 IAM 역할 | 이름만으로 편입하지 않고 기존 소유자 영역 유지 |

`외부 관리`는 불필요한 자원이라는 뜻이 아니라 이 Terraform 상태가 변경 책임을 갖지 않는다는 의미.

## 알려진 운영 예외

- 팀 테스트를 위해 별도로 만든 보안 그룹이 관리 대상 EC2에 연결된 상태
- 해당 변경은 이 저장소의 영구 구성에 포함하지 않고 팀이 직접 관리하는 예외로 수용
- 이 예외가 유지되는 동안 project plan에 네트워크 차이가 표시될 수 있으며 이를 Terraform 구성 오류로 해석하지 않음
- 예외를 종료할 때는 보안 그룹 연결을 코드 기준으로 되돌리거나 별도의 관리 자원으로 정식 편입해야 함

## 완료 판단

- 장기 운영할 핵심 서버·종속 자원·Terraform 접근 경로의 코드화 완료
- 기본·공유 자원은 조회, 자동 생성·배포·서비스 자원은 외부 관리, 소유 근거가 없는 자원은 관리 제외로 경계 확정
- 알려진 운영 예외를 제외한 추가 import를 이번 마이그레이션의 완료 조건으로 두지 않음
- 새로운 AWS 자원을 추가할 때 생성 주체와 상태 파일 소유자를 먼저 결정한 뒤 관리 경계 갱신
