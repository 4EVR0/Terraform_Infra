# 모니터링 공개 SSH 경로 단계적 제거

## 목적

- 모니터링 EC2에서 프로젝트 공용 SSH 보안 그룹 제거
- 공개 SSH 대신 검증된 AWS Systems Manager 관리 채널 사용
- 모니터링 전용 서비스 통신과 다른 서버의 연결은 그대로 유지

## 대체 관리 경로 검증

- 모니터링 IAM 역할에 Systems Manager 관리 정책 연결 완료
- 중지된 모니터링 서버를 잠시 시작해 SSM Agent `Online` 확인
- SSM Run Command로 root 권한의 진단 명령 실행 성공
- 검증 후 서버를 기존 중지 상태로 복구하고 후속 plan의 `No changes` 확인

공개 SSH 연결을 제거한 뒤에도 AWS 권한을 통해 장애 진단과 복구 명령을 실행할 수 있는 상태.

## 구현

- 모니터링 EC2의 보안 그룹 집합에서 공용 SSH 그룹 참조 제거
- 모니터링 전용 보안 그룹 참조 유지
- 공용 그룹 본체·규칙과 다른 EC2 연결은 변경하지 않음
- 계획 검사기로 정확한 대상·제거 그룹·보존 그룹과 다른 자원 무변경 검증

## 계획 검증 결과

- `terraform fmt -check -recursive` 통과
- `terraform validate` 통과
- Python 테스트 25개 통과
- 최종 plan: **0 to add, 1 to change, 0 to destroy**
- 계획 검사기: 모니터링에서 공용 그룹 하나만 제거, 전용 그룹 유지, 다른 관리 자원 변경 없음

## 적용 게이트

1. PR 병합 후 `main`에서 새 plan 생성
2. 적용 직전 원격 state 백업
3. 저장된 plan 검사 통과 확인
4. 사용자 apply로 보안 그룹 연결 변경
5. 모니터링에 전용 보안 그룹만 남았는지 확인
6. 공개 TCP 22 경로가 차단됐는지 확인
7. 모니터링 시작 후 SSM Agent와 root 명령 재검증
8. 서버를 기존 중지 상태로 복구하고 후속 plan의 `No changes` 확인

새 plan이 서버 교체나 다른 자원 변경을 포함하면 적용을 중단. 적용 후 SSM 연결에 문제가 생기면 AWS 관리 권한으로 기존 공용 그룹을 다시 연결하고 원인을 확인.

## 트레이드오프와 후속 작업

- 기존 SSH 키를 이용한 공개 접속 경로는 사라지고 IAM으로 통제되는 SSM이 기본 관리 경로가 됨
- 공개 포트를 줄여 공격 표면을 축소하고 SSM 명령 이력으로 관리 작업을 추적할 수 있음
- 대화형 Session Manager 사용성과 팀 IAM 주체의 최소 권한은 별도 검토 필요
- 공용 SSH 그룹은 파이프라인 서버의 관리 경로와 보존 여부를 결정한 뒤 최종 정리 가능
