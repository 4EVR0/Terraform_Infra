# AWS 인벤토리 조사 및 기록 방법

## 목적

수동으로 운영하던 AWS 자원을 Terraform에 편입하기 전, 실제 자원과 의존 관계 파악.
서비스별 조회 범위를 기록해 “자원 없음”과 “아직 확인하지 못함”을 구분.

## 실행 및 보관

1. Git에서 제외된 로컬 설정으로 대상 계정 확인
2. `scripts/inventory.py --all-regions --expected-account-id "$AWS_EXPECTED_ACCOUNT_ID"` 실행
3. `inventory/raw/<UTC 시각>/manifest.json`에서 조회 범위·오류 확인
4. 각 JSON 응답과 기존 배포 코드를 대조해 실제 사용 관계 검토
5. 상세 작업 일지와 자원별 관리 범위를 `docs/private/`에 기록
6. 공개 가능한 도구·방법 변경만 작업 단위로 커밋

`--all-regions`는 계정에서 활성화된 리전의 **스크립트에 구현된 API**를 호출하는 옵션. 모든 AWS 서비스와 모든 하위 자원을 빠짐없이 조사한다는 의미는 아님.

## 조회 범위

| 범위 | 조회 대상 |
|---|---|
| 리전 검색 | 활성 리전 목록 |
| 컴퓨팅·네트워크 | EC2, EBS, 자체 소유 스냅샷, VPC, 서브넷, 보안 그룹, 라우팅, IGW, NAT, EIP, ELBv2·Classic ELB, Auto Scaling |
| 실행 플랫폼 | ECS·EKS 클러스터 목록, Lambda 함수 요약 |
| 데이터 | RDS 인스턴스·클러스터, DynamoDB 테이블 목록, ElastiCache 클러스터, SQS 큐 목록 |
| 파이프라인 | ECR 저장소·정책, Glue DB·테이블 요약, Athena 작업 그룹 목록 |
| 운영 | CloudWatch 로그 그룹·알람 요약, 기본 EventBridge 버스의 규칙, AWS Backup 저장소 목록, KMS 별칭 |
| 글로벌 | S3 버킷·접근 설정, Route 53 호스팅 영역, CloudFront 배포, IAM 역할·사용자·OIDC 목록 |
| EC2 연결 권한 | 프로파일, 연결된 역할의 관리형·인라인 정책 본문 |

S3 객체 본문, EC2 user data, Lambda 환경 변수, 비밀 저장소의 실제 비밀값은 수집하지 않음. 정책·리소스 메타데이터도 운영 정보이므로 원본 응답은 공개하지 않음.

## 결과 해석

- `ok=true`: 해당 API 응답 확보. 빈 목록이면 해당 조회 범위 내 자원 없음
- `ABSENT`: 선택 설정이 존재하지 않는다는 명시적 API 응답
- `UNRESOLVED`: 권한·네트워크·시간 초과 등으로 조사 실패. 자원 없음으로 해석 금지
- 미조회: 호출하지 않은 서비스·하위 자원. 별도 후속 목록에 기록
- 오류가 있으면 종료 코드 1 반환. 오류가 있어도 이미 수집한 응답과 manifest는 로컬 보관
- 대상 계정 확인 실패 시 자원 조회 이전 중단

## 관리 범위 판단 기준

| 분류 | 판단과 처리 |
|---|---|
| 프로젝트 전용 | 실제 사용 관계 확인 후 import 후보로 등록 |
| 계정 기본·공유 | 존재만으로 프로젝트 소유로 판단하지 않고 참조 대상으로 유지 |
| 서비스 생성·자동 관리 | 서비스 또는 파이프라인과 Terraform의 이중 관리 방지 |
| 소유 불명 | 자원 이름·태그·코드 참조·팀 운영 기록을 대조한 뒤 결정 |

정책 연결을 조회했다고 다른 워크로드의 공유 여부까지 확정할 수는 없음. 팀 운영 기록 확인이 필요한 항목은 별도 표기.

## 남는 조사 한계

- ECS 서비스·태스크, EKS 노드 그룹, SQS 속성, DynamoDB 설정 등 목록 아래의 세부 설정은 추가 조회 필요
- EventBridge 사용자 정의 버스·타깃·Scheduler, CloudFormation, Secrets Manager 메타데이터, SSM 등 미포함 서비스 존재
- KMS 별칭은 키 전체 목록이 아니며, AWS 관리형 별칭과 고객 관리형 키 구분 필요
- 역할 목록 조회와 EC2 연결 역할의 정책 조사는 계정 내 모든 IAM 주체의 권한 분석을 대체하지 않음
- 버킷 ACL·정책·공개 접근 차단은 각각 따로 확인하고 조합해 판단
- Terraform import 가능 여부·구체적인 리소스 주소는 해당 provider 문서와 실제 plan으로 별도 검증

## 회귀 검증

`python3 -m unittest discover -s tests -v`

- 잘못된 계정에서 자원 조회 중단
- 활성화된 모든 리전의 EC2 조회 수행
- 권한 거절을 미확인 항목으로 기록하고 실패 종료
- 선택 정책 부재를 알려진 부재로 기록
